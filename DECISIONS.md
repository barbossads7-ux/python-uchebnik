# DECISIONS

## Статус (22.10.2026)

Ядро v1 готово: главная с прогрессом, слайды тем с запуском примеров, экран заданий с редактором.
Запуск Python: Pyodide в Web Worker, «▶ Запустить», вывод, ошибки, ввод для `input()`, таймаут, «Стоп».
Задания: CodeMirror 6, поле «Ввод», запуск/стоп, «Показать решение» + «Загрузить в редактор», «Отметить решённым»,
сохранение кода, ввода и отметок.
`npm run build` проходит. Проверено в браузере (dev и собранный `dist` через `vite preview`): ширина 375 и десктоп,
светлая и тёмная тема, стрелки, свайп, сохранение прогресса, запуск примеров, вечный цикл, нехватка ввода, рекурсия.

## Как раздавать сайт (без Vercel)

- **Один файл:** `npm run build:single` → `dist-single/python-uchebnik.html` (≈1,1 МБ, 0,5 МБ gzip). Внутри всё:
  код, стили, шрифты, курс. Отправить файл → открыть двойным щелчком в браузере на компьютере.
  Интернет нужен только для Python (Pyodide с CDN) при первом запуске кода.
- **Сайт по ссылке: https://barbossads7-ux.github.io/python-uchebnik/** (GitHub Pages, репозиторий
  `barbossads7-ux/python-uchebnik`, публичный — бесплатный Pages только для публичных; конспект виден всем).
  `.github/workflows/deploy.yml`: на каждый push в `main` — `npm ci` → `npm run build` → публикация `dist/` (~1 мин).
  Обновить сайт: поправить md → `git add -A && git commit -m "…" && git push`.
- **Прогресс у каждого свой:** он в `localStorage` браузера, на сервер ничего не уходит.
  Ограничения: прогресс привязан к браузеру и устройству (нет синхронизации); очистка данных сайта его стирает;
  у файла с диска хранилище общее для всех `file://`-страниц этого браузера (ключ у нас уникальный, это не мешает).
- **Телефон:** открыть HTML-файл с диска на телефоне неудобно (iOS «Файлы» показывает предпросмотр без JS).
  Для телефона — хостинг (`dist/`).

## Принятые решения

### Контент
- **md разбирается при сборке** Vite-плагином (`course-build/vite-plugin.ts` → модуль `virtual:course`).
  Почему: сломанный md роняет `npm run build` с понятной ошибкой; в браузер не едут marked и парсер (в бандле их нет).
  В dev правка `content/*.md` перезагружает страницу.
- **`npm run dump`** печатает, как md разрезан на слайды и задания: проверка парсера без открытия сайта.
- **Правила разбивки теории:**
  - тема — `## Тема N. Название`; темы идут по порядку с 1; тема заканчивается на первой строке `---`;
  - текст после `---` последней темы — сноска внизу главной; такой же текст между темами — ошибка сборки;
  - тема с `###`: каждый `###` = 1 слайд (длинный слайд прокручивается — решение пользователя);
    вступление до первого `###` с кодом — отдельный слайд с названием темы, без кода — приклеивается к первому слайду;
  - тема без `###`: граница — абзац, начинающийся с жирного текста (он же заголовок слайда);
    кусок без кода приклеивается к следующему; если кусок длиннее ~22 строк — делится по блокам,
    абзац с «:» в конце не отрывается от следующего блока, длинный нумерованный список делится по пунктам с продолжением нумерации.
  - Итог: 7 · 2 · 5 · 2 · 5 · 5 · 5 · 2 слайдов в темах 1–8.
- **Задания:** `**N.M 🟢|🟡|🔴**` + всё до следующего задания (так в 1.3 в условие входят код и абзац после него).
  Решения — `### N.M` после второго `# …`. Связь с темами — по номеру (в файле заданий тема 6 называется иначе).
  Ошибки сборки: задание без решения, решение без задания, дубль, неизвестный значок уровня, задание не в своём разделе, тема без теории.
- **Шапка файла теории:** на главной показывается только первый абзац («Составлено по конспекту…»), «Содержание» строится по заголовкам.
- **Шапка файла заданий** («решения — в конце файла») не показывается: на сайте решения не в конце файла, а под каждым заданием.
  Подписи уровней («простое / посложнее / со звёздочкой») — подписи интерфейса в `Topic.tsx`.
- **Метка `[дописано…]`** отображается значком; текст md не меняется.
- HTML из md вставляется без санитайзера: источник — только наши файлы в `content/`.

### Подсветка кода
- `@lezer/python` + `classHighlighter` из `@lezer/highlight` при сборке → классы `tok-*`, цвета в `src/styles/code.css`.
  CodeMirror 6 построен на тех же пакетах: в редакторе подключим `syntaxHighlighting(classHighlighter)` — цвета совпадут.

### Запуск Python
- **Pyodide 314.0.7** с официального CDN `cdn.jsdelivr.net/pyodide/v314.0.7/full/` (≈12 МБ: wasm 9,6 + stdlib 2,5).
  Версия одна на всё: пакет `pyodide` закреплён в devDependencies (из него только типы), `vite.config.ts` берёт его версию для URL.
- **Ленивая загрузка:** воркер и Pyodide создаются только при первом «▶ Запустить» (на главной и при листании ничего не грузится).
  Пока грузится — «Загружаю Python…»; ошибка сети → «Не удалось загрузить Python» + «Повторить»; загрузка дольше 90 с = ошибка.
- **Web Worker** (`src/python/python.worker.ts`, ES-модуль; `worker.format: 'es'`). Pyodide грузится через `import()` по URL.
- **Таймаут 5 с и «Стоп» = `worker.terminate()`**. Прервать Python мягко можно только через SharedArrayBuffer,
  а это требует заголовков COOP/COEP на хостинге — для статического сайта не берём. Цена: после остановки Python
  загружается заново, из кэша браузера ≈0,7 с (замерено).
- **Один запуск за раз** на всю страницу; остальные кнопки неактивны («Сейчас выполняется другой пример»).
  Уход со слайда во время выполнения останавливает программу.
- **Каждый запуск — чистое пространство имён** (переменные между примерами не «протекают»).
- **`input()`** подменяется в пространстве имён: печатает подсказку и введённое значение, как терминал;
  строки берутся из поля «Ввод (каждое значение с новой строки)» — оно появляется только у кода, где есть `input(`.
  Строки кончились → понятная ошибка «не хватает ввода».
- **Вывод:** stdout в режиме tty (построчно — вывод вечного цикла виден до остановки), stderr красным;
  пачки сообщений не чаще 50 мс; не больше 100 000 символов («Вывод слишком длинный — показано начало»).
- **Ошибки:** «Ошибка в строке N» + сама строка кода + пояснение по-русски (`src/python/errors.ts`) + оригинал `Type: message`.
- **Значения выражений на слайдах** печатаются, как в консоли Python (верхнеуровневые выражения, кроме `None`),
  и выделены цветом с подписью. Иначе примеры вроде `int("25")` (1.4, 1.5, 3.5, 5.2) ничего бы не выводили.
  Для заданий этот режим будет выключен — там обычная программа.
- **Блоки, которые Python не разберёт** (Lezer находит синтаксическую ошибку при сборке — сейчас только первый блок 7.2),
  без кнопки, с подписью «Это схема записи, а не программа». Шаблоны, которые разбираются (тема 4, 5.5),
  запускаются и честно показывают NameError с пояснением.
- Кнопки «Запустить» только на слайдах: в условиях заданий их нет (3.3 прямо просит «не запуская, предскажи»).

### Экран заданий
- **CodeMirror 6, собран вручную** (не `basicSetup`: без поиска, автодополнения, сворачивания — меньше и проще):
  номера строк, история, подсветка скобок, автозакрытие скобок/кавычек, автоотступ, `@codemirror/lang-python`,
  `syntaxHighlighting(classHighlighter)` — цвета те же, что на слайдах (`code.css`). Тема — CSS-переменные, тёмная работает сама.
- **Tab:** без выделения — пробелы до следующей позиции, кратной 4; с выделением — сдвиг строк; Shift+Tab — назад.
  Чтобы не запирать клавиатуру: **Esc, затем Tab** уводит фокус из редактора (встроено в CodeMirror; подсказка под редактором).
- **Ctrl/⌘+Enter — запустить** (перекрывает стандартное «вставить пустую строку»). Подсказка скрыта на сенсорных экранах.
- **CodeMirror грузится лениво** (`React.lazy`): отдельный чанк ≈126 КБ gzip, только при открытии экрана заданий.
  Основной бандл остался ≈94 КБ gzip.
- **Начальный код:** python-код из условия (1.3 — словарь, 3.3 — код для предсказания), иначе пусто с подсказкой.
- **Поле «Ввод»** над редактором: показывается, если `input(` есть в коде или в решении, либо поле уже заполнено.
- **Запуск в заданиях — без печати значений выражений** (обычная программа, не консоль).
- **«Загрузить в редактор»** — только если в решении есть python-код (у 3.3 нет: там ожидаемый вывод).
  Свой код не теряется: появляется «Вернуть мой код»; ещё замена — одна правка в истории (Ctrl/⌘+Z).
- **Сохранение:** код и ввод — через 400 мс после последнего изменения, плюс при уходе со страницы (`pagehide`)
  и при размонтировании. Отметка «решено» — сразу. Счётчик «Задания N / M» на главной обновляется.
- 16px шрифт в редакторе и поле ввода на сенсорных экранах — иначе iOS увеличивает страницу при фокусе.
- Кнопка «Следующая тема» внизу экрана заданий не липкая — иначе закрывала бы редактор.

### Сборка в один файл
- `vite-plugin-singlefile` 2.3.3 (взята версия апреля, не свежая 2.3.4 от 17.10), режим `--mode single`.
- **Воркер запускается из `data:`-URL** (`course-build/worker-source-plugin.ts` компилирует `python.worker.ts` в строку).
  Проверено в headless Chrome на `file://`: модульный воркер из `blob:` там не стартует (а запасной вариант Vite
  на `data:` не срабатывает — ошибка асинхронная), из `data:` — работает и грузит Pyodide с CDN.
  Один путь для всех режимов: dev, `dist/`, один файл. В воркере не должно быть runtime-импортов — плагин это проверяет.
- **До 3 попыток загрузить `pyodide.mjs`** с паузой 1–2 с; повтор с `?retry=N`, потому что браузер запоминает
  неудачный `import()` по URL. Нужно было: первый запрос на «холодном» соединении иногда падал.
- Шрифты — только латиница и кириллица (раньше тянулись все подмножества) — меньше файл.
- Фавикон — `data:` в `index.html`, без отдельного файла.

### Фронтенд
- Свой hash-роутер (`src/router.ts`, без react-router): `#/`, `#/topic/N` (продолжить с последнего слайда),
  `#/topic/N/slides/K` (K с 1), `#/topic/N/tasks`. Неверный номер слайда — замена в истории на ближайший допустимый.
- Прогресс — `localStorage`, ключ `python-uchebnik/progress/v1`; все обращения в try/catch; синхронизация между вкладками.
  Задания: `tasks[id] = { code, stdin, solved }`.
- «Слайды пройдены» = самый дальний открытый слайд темы. Тема с ✓ — все слайды открыты и все задания отмечены.
- Навигация: кнопки, клавиши ←/→ (не срабатывают при вводе текста), свайп только для touch/pen и не внутри `pre`/таблиц.
  На последнем слайде «К заданиям»; в теме без заданий — «Следующая тема» / «На главную».
- Анимация: сдвиг 28px + fade, 230 мс, `animation-fill-mode: backwards`; при `prefers-reduced-motion` выключена.
  `.topic { overflow-x: clip }` — иначе Chrome оставлял 12px горизонтальной прокрутки после анимации.
- Шрифты Manrope / JetBrains Mono — пакеты `@fontsource` (работают офлайн, без запросов к Google).
- `base: './'` — собранный `dist/` открывается из любой папки или со статического хостинга.

## Открытые проблемы
- Перезагрузка dev-страницы при правке md написана (`handleHotUpdate`), но не проверена вживую: md без спроса не трогаем.
- Порог «~на экран» (22 строки по 55 символов) — оценка; тема 8 делится 1–3 / 4–8, второй слайд длиннее экрана телефона и прокручивается.
- Шаблоны темы 4 и 5.5 при запуске дают NameError (`условие`, `data`) — объяснение есть, но может смутить.
  Если мешает — можно прятать кнопку и у них (нужно правило, как отличить шаблон от программы).
- Офлайн-кэш Pyodide (Service Worker) не сделан — работает только HTTP-кэш браузера.
- Кнопка «Стоп» вживую проверена в редакторе задания (`while True: pass`); на слайдах нет долгого примера.
- Набор кода с телефона (экранная клавиатура) не проверялся на реальном устройстве — только эмуляция ширины 375.
- Если таймаут сработал, а вывод был обрезан, подпись «показано начало» не появится (видно сообщение о таймауте).
- Решение 3.3 — ожидаемый вывод, не код (блок без `python`): кнопку «Загрузить в редактор» для него не показывать.

## Следующие шаги
1. Проверить на реальном телефоне по ссылке: свайп слайдов, набор кода, поле ввода
   (по ссылке проверено только в эмуляции ширины 375: слайды, запуск Python, редактор).
   Файл с диска проверен только в Chrome (headless); Safari и Firefox на `file://` не проверялись.
2. Решить, нужен ли офлайн-кэш Pyodide (Service Worker).
3. Возможно: кнопка «Сбросить к началу» в задании (сейчас вернуть начальный код можно только вручную).
